# Claude Desktop セッション一覧のサンプルデータ（合成）

`/desktop-sessions`（Desktopセッション）画面の動作確認とテスト用に作った、**すべて架空のデータ**です。
実際のセッション名・ID・パスは含みません。Claude Desktopの内部形式に似せた次のファイルで構成されています。

| 場所 | 内容 |
|---|---|
| `data/claude-code-sessions/<アカウント>/<組織>/local_*.json` | セッションごとのメタデータ（6件） |
| `data/claude_desktop_config.json` | サイドバーのグループ・ピン留め。`mcpServers` は「APIに出ない」ことの確認用のダミー |
| `data/config.json` | 実際のDesktopでは認証トークンが入るファイル。Dashboardは**読みません**（ダミー） |
| `projects/<フォルダ>/<cliSessionId>.jsonl` | 会話ログ（`~/.claude/projects/` の代わり。5件。1件は会話ログなし） |

## 画面で確認する方法

`config/desktop-sessions.json`（Gitの管理対象外）を次のように作り、開発サーバーを起動します。パスは自分の環境のものに置き換えてください。

```json
{
  "dataDir": "<このリポジトリ>/sample-data/claude-desktop/data",
  "projectsRoot": "<このリポジトリ>/sample-data/claude-desktop/projects"
}
```

状態の「実行中」は会話ログの更新時刻から推定するため、ファイルをコピーした直後は全件が実行中に見えます。
確認用に、更新時刻を過去へずらしてください（PowerShellの例。`001` の会話ログだけ数十秒前のままにすると「実行中」になります）。

```powershell
Get-ChildItem sample-data/claude-desktop/projects -Recurse -Filter *.jsonl |
  Where-Object { $_.Name -notlike '*000000000001.jsonl' } |
  ForEach-Object { $_.LastWriteTime = (Get-Date).AddHours(-3) }
```

## 組織図の確認用データを作る

`/desktop-sessions/org`（サイドバーの「組織図」。指示・報告・他グループ連絡の動き）の確認用に、すべて架空のデータを作るスクリプトがあります。
現在時刻を基準に直近4時間の出来事を作るので、画面を開く直前に実行してください（古くなったら作り直します）。

```bash
node scripts/make-org-chart-sample.mjs <出力先のフォルダ>
```

表示された `dataDir` と `projectsRoot` を `config/desktop-sessions.json` に書いて、ダッシュボードを（再）起動します。この PC の本物の Claude Desktop のデータを読まないよう、起動のときに環境変数 `CCD_DESKTOP_AUTODETECT=0` を付けてください（設定ファイルで指定した場所だけを読みます）。撮る・確かめる前には `node scripts/check-sample-server.mjs <サーバーのURL> <出力先のフォルダ>` で、合成データだけを読んでいることを確かめられます。
利用上限のゲージも見るときは、表示された `snapshotsPath` と `projectsRoot` を `config/usage.json` に書きます（出力先の `usage-snapshots.jsonl` が、架空の公式値の記録です。5時間 22%・週 14%）。
上限ガードの帯（「上限ガード中：新しい指示は保留中です」）を見るときは、`--guard` を付けて作ります（最後の5時間が92%になる）。

```bash
node scripts/make-org-chart-sample.mjs --guard <出力先のフォルダ>
```

同じ出力先に合成データを作り直したときも、ダッシュボードを再起動してください（会話ログの読み込みは差分読みなので、再起動しないと古い値のまま残ります）。
既定の接頭辞 `00_` で、グループ「試験グループ」（指揮役1・子4。3層目あり）と「別グループ」（指揮役1・子1。3層目1）が見えます。

「試験グループ」で確認できること:

- 指示8本（受け手の会話ログまで確認できたもの7、送り手の記録だけのもの1）、報告5本、報告なしで終了2件（その間のツール呼び出し 30回・19回）
- 他グループからの連絡1件と、外部（CLI）からの連絡1件（指揮役のカードに点線で入る）
- 作業中の子1件（カードが脈動する）、コンテキストの圧縮1件、コンテキスト80%超・90%超の子、送信上限（10回）で停止中の子1件

3層目（子が作った補助のセッション。親はメタデータの `spawnedFrom.sessionId` で指す。名前順と作成順が食い違うように作ってあります）:

- 「01_画面の修正」の下に「補助A」「補助B」の2件。補助B（グループの外）は、子との指示1本・報告1本（作業6回）のやりとりがある。補助A（4層目。補助Bが作ったもの）は、2層目の祖先「01_画面の修正」の下にまとめて出る
- 「03_検証」の下に「補助C」（グループ内の子が作った、グループ内のセッション）
- 「04_文書の整備」の下に「補助D」。指示も報告も無いが、直近のツール呼び出しで「作業中」になる
- 指揮役が作った、グループの外のセッション「補助_臨時の調べもの」（2層目に出る）
- 木に出ないもの: 親が見つからないグループ外のセッション、アーカイブ済みのセッション
- サイドチャット「脇の質問_用語の確認」（「01_画面の修正」から開いた脇の会話。メタデータの `spawnedFrom.btw` と `spawnedFrom.userFork` が true）はカードにならず、「01_画面の修正」のカードに「サイドチャット 1」と出る。同じ親の作業用の子「補助B」（`spawnedFrom.sideSession` だけが true）はカードになる。セッション一覧では「サイドチャット（親：01_画面の修正）」の印が付く
- 「別グループ」の「01_調査」の下に、グループ外のセッション1件（3層目）

### 整理ページの確認

同じ合成データで、`/desktop-sessions/housekeeping`（サイドバーの「整理」）も確認できます。どのグループにも入っていない「判断_」で始まる4件（質問の回答待ち・要約が「要対応」・エラー・宛先不明の送信）を足してあります。

- 判断待ち5件: 要対応2（回答待ち・要約が要対応〈内容の先頭60文字が出る〉）→ 送信上限で停止中1（03_検証）→ エラー1 → 届かなかった送信1
- 返事の来ていない指示4件（古い順）: 報告なしで終了2（02_集計の作成・03_検証）、未達の疑い1（04_文書の整備。送り手の記録だけ）、報告待ち1（01_画面の修正。作業中）
- コンテキスト整理の候補10件: 再開コストの大きい順（03_検証が先頭。コンテキストが大きい＋長く止まっている）。最後は、コンテキストは大きいがキャッシュが有効なもの（04_文書の整備）で、再開コストは出ない
- 再開コストを「5時間の枠 約x〜y%・週 約x〜y%」で見るには、利用上限の公式値の記録（`config/usage.json` の `snapshotsPath`。スクリプトが出力先に `usage-snapshots.jsonl` を作る）が要ります。無ければ、金額（API価格換算）だけが出ます。記録は1行1件のJSONです（形式は `src/lib/usageSnapshots.ts` の先頭の説明）

期待値はスクリプトの戻り値（`expected.housekeeping`）にあり、`src/lib/housekeepingService.test.ts` が同じ値を確かめています。

### 組織のルールの確認

同じ合成データで、`/org-rules`（サイドバーの「組織のルール」）も確認できます。スクリプトは、出力先に次のファイルも作ります。

- `global/CLAUDE.md`：全体の決まり（合成）。「組織の運用」「セッションの題名」の節と、無効にした節が1つ。古い名前「06_集計の作成」を含む
- `work/leader-a/CLAUDE.md`：「00_リーダー_試験」の作業フォルダの決まり。古い名前「05_検証」を含む（「別グループ」の指揮役の作業フォルダは `work/leader-b`）
- 指揮役の記憶（会話記録のあるフォルダの `memory`）：索引 `MEMORY.md` に載っていない記憶が1件、索引にあるのにファイルが無いものが1件、古い名前「08_文書の整備」を含む記憶が1件
- 指揮役でないセッションのフォルダの記憶：画面に出てはいけない合成の目印を含む（読んでいないことの確認用）
- `extras/ledger.md`：追加のファイル（台帳）の見本

画面に出すには、スクリプトの最後に表示される `org-rules.json` の内容を、`config/org-rules.json` に保存します（`globalClaudeMdPath` と `extraFiles`）。期待値はスクリプトの戻り値（`expected.orgRules`）にあり、`src/lib/orgRules.test.ts` が同じ値を確かめています。

ライブで動きを見るには、画面を開いたまま、会話ログ（`projects/` の下の `.jsonl`）の末尾に、指示・報告に当たる行を追記します。
追記した行だけが粒として流れます（開いた直後に過去の出来事を一斉に再生することはありません）。
期待する件数は、スクリプトの最後に表示されます。
