# Claude Code Dashboard

Claude Code とのやり取りにおける「ルール」「スキル」「実行ログ／思考プロセス」をローカルで可視化・管理するダッシュボード。
Webアプリ側は重い処理を行わず、実際の `.claude/CLAUDE.md` / `.claude/skills/*/SKILL.md` / `execution_log.json` を直接
読み書きして描画するだけのCPUモード（外部API通信なし・コスト0円）で動作する。

使い方（起動・各ページの見方・リソース・利用上限と送信上限・整理ページ・安全の設計・困ったとき）は [使い方ガイド](docs/manual/使い方ガイド.md) を参照。

## 実装済み機能

- **ホーム**（`/`）— いちばん上に、利用上限の1行の帯（5時間・週の%。80%以上か上限ガード中は太字の「！ 新しい指示を控える」。その上に、⑭ の PC の警告の1行〈直近10分は赤い枠、過ぎてから24時間は灰色。無いときは出ない〉）と、**次にやる判断**（⑬）を出す。次にやる判断は、あなたが答える・押す・開いて一言入れるまで止まっているセッション（許可待ち・承認待ち・質問・種類不明・送信上限で停止・エラー・届かなかった送信。待機は入れない。数え方は整理ページの件数・通知・セッション一覧の「要対応」の件数カードと同じ `collectDecisions`）を、急ぎ（送信上限・許可・エラー・立てたセッションが答えを待っている）・今日中（承認・届かない送信・待ち2時間以上）・いつでもの順に並べ（7日以上そのままのものは、理由があっても「いつでも」の最後に下げ、件数に「うち7日以上 n」と出す。「コミットの許可をください」のように許可の語とコミット・push などの語が同じ文にあるものは承認）、最初は5件まで（急ぎは全部）と［ほか n件を出す］。各行は、種類・題名・問いの文（wrap_up の ask → AskUserQuestion の先頭の問い → ExitPlanMode の1行目 → 要約の needs_action の順。3行まで、超えると［全文を開く］。許可は結果を待っているツールの先頭40字で、秘密らしい文字列を伏せる）・答えの候補（AskUserQuestion の選択肢と wrap_up のボタンの名前だけ。推しは「(Recommended)」「（推奨）」の印のあるものと、wrap_up の問いのときの先頭のボタン〈wrap_up の道具が推しを先頭に置くため〉）・待ち時間と、Claude Desktop でそのセッションを開く［セッションを開く］。問いの全文と候補をサーバーが返すのは、判断を待つセッションだけ（`src/lib/decisionDetail.ts`。パスはスマホと同じ関数で隠す）。答えはダッシュボードからは送らない。判断の要らないセッションは状態ごとの件数を1行で出す。その下に組織図（前回見ていたグループ）と、組織図に出ていないセッションの件数・組織の「つながり」への入口の1文。選んでいるプロジェクトは使わない。遅い PC でも段階を追って出す（⑫）：見出しと枠は静的な HTML に入り、件数と利用上限 → 次にやる判断の問い → 組織図の順に出し、1.5秒以上待ったときだけ上のバーに段階の印を出す。30秒たった欄には「時間がかかっています（30秒以上）。このまま待てます」と［もう一度読み込む］を、サーバーが失敗を返した欄には「読み込めませんでした」と［もう一度読み込む］を出す。サーバーは起動の直後に一覧と利用上限の台帳を裏で読み始める（`src/instrumentation.ts`）
- **ルール管理**（`/rules`）— `CLAUDE.md` の `## 見出し` をルールとして直接パース。ON/OFFトグル（`<!-- CCD:DISABLED -->` で無効化）、追加/編集/削除（削除は確認ダイアログつき。CLAUDE.mdを書き換えるたびに直前の内容を自動で退避）、ドラッグ&ドロップによる表示順（=CLAUDE.mdの記載順）の並び替え、次回用プロンプト集（実行ログ由来）
- **スキル管理**（`/skills`）— `.claude/skills/*/SKILL.md` の一覧・追加・編集・削除（確認ダイアログつき。完全削除はせず`skills-trash/`へ退避し、「削除済みスキル」から復元できる）・改名（ディレクトリ名変更。呼び出しコマンドが変わる旨を確認表示）・カテゴリ別グルーピング表示（frontmatterの`category`フィールドに基づく表示上の分類。実ファイルはフラット配置のまま。初めは閉じる）・有効/無効の切り替え（無効にすると`skills-disabled/`へ移し、Claude Codeから呼び出せなくなる）。対象モデル（frontmatterの`target-model`。自由入力）と成熟度（`references`/`scripts`/`evals`サブフォルダの有無）は各カードの「詳しく」に、似ているスキルの組（同じカテゴリ内でdescriptionが似た組）は閉じた欄に出す（数が増えたときだけ役立つので、初めは閉じる。⑬）。モデル別アーカイブと世代の切り替えは、スキル5個では使う場面が無いのでやめた（⑬。版は「バックアップ」と「削除済みスキル」で戻せる）
- **設定 & システム情報**（`/settings`）— `settings.json`（権限モード・環境変数・statusLine）を読み取り専用で表示し、バックアップのタブには、Claude Code本体の`.claude.json`バックアップと、このダッシュボードが書き換え・削除の直前に作った退避（`*.ccd-backup.<epoch>`）が並び、復元できる（復元の直前の内容も退避される）。JSON の直接の編集（壊すと Claude Code が動かない）と、見ても何もできないブロック済みプラグインの一覧は、⑬ でやめた。下の「ページを開いた回数」（指示47・FS-7）は、スイッチ「開いた回数を数える」（初期値オン）と、直近7日・30日・最後に開いた日の表。サイドバーの13ページのパスと日付ごとの回数だけを `config/page-visits.json` に保存し（直近30日）、画面からは1日1パス1回・まとめて1分に1回まで送り、サーバーもファイルへは1分に1回まで書く。外部へは送らない。書き込みは PC の画面からだけ
- **スマホから見る**（`/lan-access`）— 同じ家の Wi-Fi のスマホから、ホーム・セッション一覧・利用上限・整理の4ページを読み取り専用で見る（既定はオフ）。Next のサーバーは 127.0.0.1 のままにし、オンのときだけ別の入り口（`src/lib/lanAccess/gateway.ts`。番号 38418）が PC のプライベートな IPv4 で待ち受けて、判定（`gatewayPolicy.ts`）を通った GET・HEAD だけを中継する（Next の proxy では相手のアドレスが分からず、Host を偽るとループバック扱いになるため）。入り口は、Host が PC の IP:38418 であること・接続元がプライベートな IPv4 であること・登録した端末の鍵（HttpOnly・SameSite=Strict のクッキー。サーバーはハッシュだけを持つ）・許可リストを確かめ、書き込みは鍵があっても 403。端末は PC の画面の登録コード（QR・5分・1回限り）で登録し、期限は90日、10台まで、端末ごとに取り消せる。スマホへ返す API の応答では、作業フォルダのパスを最後のフォルダ名だけにする。入り口は `src/instrumentation.ts` で起動し、オン・オフは再起動なしで反映する。通信は HTTP（暗号化なし）なので、家の Wi-Fi の中だけで使う。スマホにはスマホ用の画面（`src/app/phone`・`src/components/phone`）を出す。proxy が入り口の経由の要求だけを振り替えるので、URL は PC と同じで、PC のページの描き方（静的）は変わらない。最初の画面に、あなたの対応待ち（件数と上位3件。問いの文を16pxで3行まで出し、入りきらないときだけ［全文を開く］。スマホへ返す問いと候補は、秘密らしい文字とパスを伏せる）・送信上限で停止・実行中の数・利用上限を出し、下の4つのタブで移る。一覧は1件1枚のカードで、詳細は全画面で開く。15秒ごとに読み直し、画面が隠れているあいだは止める。ライト・ダークは端末の設定に合わせる
- **移行（エクスポート/インポート）**（`/migrate`）— ルール・スキルを1つのJSONファイルに書き出し、他のPC（別プロジェクト）に差分プレビュー付きで取り込む。上書き前に自動バックアップ。インポートは足す・上書きするだけで、今あるルール・スキルは消さない。移るもの・移らないものを画面の上に出す（`src/lib/migrateScope.ts`）。インポートの「ファイルを選択」はドラッグ&ドロップにも対応し、配布版exeでは`dialog.showOpenDialog`をIPC経由で直接呼び出す経路を優先する（環境差でファイル選択ダイアログが開かない事例への対処）
- **セッション一覧**（`/desktop-sessions`）— Claude Desktopの全セッションを一覧する読み取り専用ビュー（5秒更新。サイドバーの「Claude Desktop」は、見たい内容ごとに「セッション一覧」「リソース」「整理」「組織」のページに分かれ、組織図はホームに出る）。一覧の主データはDesktopが保存するセッションのメタデータ（`claude-code-sessions/*/*/local_*.json`）で、要対応のセッションには要対応の内容の先頭60文字を表示し、会話ログ（`~/.claude/projects/*/<id>.jsonl`）から最新の指示（先頭60文字・発信元つき）・コンテキスト使用量・タスクリストの進み具合・圧縮回数を補い、サイドバーのグループ・ピン留めは`claude_desktop_config.json`の`preferences.epitaxyPrefs`の該当キーだけを読む。状態は、Desktopが付ける分類（要対応・確認待ち・完了）と、会話ログの更新状況からの推定（実行中・中断の可能性）を併記する。**要対応は4つに分ける**：許可待ち・承認待ち・判断待ち・待機（待機は要対応に数えず、ホームの判断待ち・整理ページ・通知から外す）。手がかりは、質問・プランの承認のツールで止まっていること、最後のターンのwrap_upの呼び出しの入力（質問の有無・承認のボタン〈commit・create_pr・merge〉）、無ければDesktopの要約の言葉（「推定」と出す。要約の詳しい文〈status_detail〉は種類を決めるのに使うだけで、返さない）。分け方は`src/lib/needsActionKind.ts`の表。Desktopの内部形式は非公開・非保証のため読み取り処理は`src/lib/desktopSessions.ts`に隔離し、読めない場合は会話ログだけの縮退表示に切り替える。認証トークンを含む`config.json`は読まず、APIは表示用の許可リスト項目だけを返す。新しく要対応になったセッションのデスクトップ通知（初期値はオフ。exeはElectron、ブラウザはNotification API。外部サービスは使わず、本文はセッション名と要対応の内容の抜粋だけ。クリックで詳細を開く）に対応（「CLIプロセスあり」の表示は、判断に使わず PowerShell を定期的に呼ぶ負荷だけが残るので、⑬ でやめた）。行を押して開く詳細には「健康」の欄があり、開くと会話ログ（`~/.claude/projects/*/*.jsonl`）から、無限ループ（沼）の兆候・ワークフローの安定性・拡張機能（MCP）の稼働・セッションの寿命の4つの観点を良好/注意/要対処で判定し、根拠・しきい値・次の行動を出す（`src/lib/sessionDiagnostics.ts` の `diagnoseHealth`。⑬ でセッション監視のページから移した）。Claude Code側のスキル`session-diagnostician`が書き出す`session_diagnosis.json`があれば、AI診断も並べる（ダッシュボード自身はLLMを呼ばない）。他のセッションへのメッセージ送信には「人が最後に入力してから10回まで」という上限があるため、各セッションに**送信回数**（送信 n/10。8回以上で黄、10回で赤。届かなかった送信も数える）を表示し、上限で止まっているセッションは**「送信上限で停止中」**を赤で目立たせて、Claude Desktopでそのセッションを開くボタン（`claude://`のリンク。exeは許可した形式のURLだけを開く）を出す。新しく停止したときのデスクトップ通知（要対応の通知と同じスイッチ）にも対応。回数は会話ログの送信ツール（`SendMessage`・セッション管理の送信ツール）の呼び出しから数え、停止は送信ツールの結果の文言から判定する（文言は非保証のため、判定条件は`src/lib/sessionMessaging.ts`の1か所に集約）。サンプルは`sample-data/claude-desktop/`（すべて合成データ）
- **リソース**（`/desktop-sessions/usage`。⑭）— 前の「利用上限」のページ。上の下線のタブで［利用上限］［作業と待ち］［負荷］を切り替える（`?tab=usage`・`plan`・`load`。前回のタブは覚えず、サイドバーから開くといつも［利用上限］）。［作業と待ち］は、各セッションが書く作業計画（`work_plan.tsv`）と利用上限の待ち行列（`resume_queue.tsv`）を読み、回復を待っているセッション（回復の見込みの時刻・残り時間・次の一歩）と、グループごとの今の作業（状態・順・大きさ・再開のしやすさ。待ち行列にいるセッションの作業中は「待ち（上限）」）を出す。［負荷］は、CPU の記録（`cpu_YYYYMMDD.tsv`。約1分ごと）を読み、PC 全体の CPU とメモリの推移の図（切り替え。1・2・6・24時間と日付。しきい値の点線・警告の斜線の帯・記録なし〈3分超の空き〉の灰色。図は role=slider で、押す・なぞる・矢印で時刻を選ぶ）、つながりの図「どこに CPU を使っているか」（上位8件・ほか・セッションの外 → PC 全体。線の太さと流れる粒が PC 全体に対する割合。粒は30回／秒まで、動きを減らす設定・止める・隠れているときは止める）、選んだ時刻に動いていたセッションの表を出す。しきい値は記録の警告の行（`CPU 85% 以上`・`メモリ 90% 以上`）の数字を読むだけで、アプリの中には持たない。PC の警告は、タブの下の帯・ホームの帯・サイドバーの「！」・通知（今の通知のスイッチ）にも出す。3つのファイルと記録の仕組みは読むだけ（書かない・動かさない）。読む場所は `config/monitor.json`（見本は `config/monitor.example.json`）。［利用上限］は、5時間・週（全モデル）・週（モデル別）の上限のゲージ（80%で黄・90%で橙・95%で赤）、リセットまでの残り時間、今のペースで何時に100%になるか（リセットより先に達する場合は警告。リセットとの差が小さい場合〈5時間の枠は15分以内・週の枠は2時間以内〉は赤でなく黄色で「リセットとほぼ同時」）、直近5時間と今週にどのセッション・グループが使っているか（上限の何%に当たるかで表す積み上げ棒。ドルは請求額と誤解されるため出さず、係数が決まらないときは全体に占める割合）を表示する。80%・95%を超えたときのデスクトップ通知（要対応の通知と同じスイッチ）、最新の公式値が80%以上（「上限に近づいています」）・90%以上（「上限ガード中：新しい指示は保留中です」）のときの帯（Claude Desktopのページの上部とホームの帯に表示。表示のみ。ガードの判断は運用ルール側）に対応。**公式値**は`~/.claude-dashboard/usage-snapshots.jsonl`（1行1件。記録は別の運用で追記する）を読み取るだけで、書かない。公式値の記録の間は、会話記録（`~/.claude/projects/*/*.jsonl`と`<セッション>/subagents/*.jsonl`）のトークン量を、`message.id`で重複を除いたうえでAPI価格で金額に換算し、公式値で較正した係数で割って**推定**する（画面には「推定」と幅を明示する。推定と公式値の差〈中央値・90%点〉は作る側の確かめなので画面に出さず、自動テストで確かめる）。モデルの価格表は`config/usage.json`の`prices`で直せる（見本は`config/usage.example.json`）。認証情報（`.credentials.json`・Desktopの`config.json`）は読まない。外部との通信なし・LLM呼び出しなし
- **組織図**（ホーム `/` に表示。以前の `/desktop-sessions/org` はホームへ移る）— グループごとに、指揮役のカードを上に、グループ内のセッションのカードを作成順に下に並べ、直近4時間の指示（指揮役→子、青い粒が下へ）・報告（子→指揮役、緑の粒が上へ。粒の大きさは作業量）・他のグループや外部（CLI）からの連絡（紫の点線）を、新しく起きたものだけ線の上の動きで見せる読み取り専用ビュー。指示と他グループ連絡は先頭20文字だけを線の横に出し、報告の本文は出さない。報告せずにターンが終わったセッションは灰色の「報告なしで終了」、作業中のカードは脈動し、カードにはコンテキストの%（80%で黄・90%で赤）と最新の指示を出す。出来事の一覧は初めは閉じる。過去を再生する「振り返り」、上の4つの集計、期間と並び順の選択、「見方」の説明、カードの作業量のバー・指示と報告の本数・トークン量・中断の可能性の印は、判断に結びつかないので ⑬ でやめた。指揮役は、グループ内でタイトルが接頭辞（既定 `00_`）で始まるセッション。接頭辞は `config/desktop-sessions.json` の `orchestratorPrefix` で変える（設定を変えたら再起動）。接頭辞に合うセッションが無いグループは、カードだけを並べて線は引かない。グループの並びの最後に「クラウドのセッション（claude.ai で開く）」を置き、`https://claude.ai/code` を新しいタブ（exe は既定のブラウザ。`electron/externalUrl.js` の許可リストに完全一致で入れた）で開く。クラウドのセッションの中身は claude.ai のログインの鍵が要るので出さない（⑬ CL-1）。指揮役の子（2層目）が作った補助のセッションは、その子のカードの下に字下げして並べる（3層目）。親は、Desktopのメタデータの `spawnedFrom.sessionId` だけで判断する。3層目はグループに入っていなくても出る（親が2層目の子のときだけ）。4層目以降は2層目の祖先の下にまとめて並べ、アーカイブ済みは出さない。サイドチャット（`spawnedFrom.btw` と `spawnedFrom.userFork` が両方 true のもの）はカードにせず、親のカードに「サイドチャット n」と数だけ出す。指示が無くても、直近1分以内にツールを呼んでいれば、カードは「作業中」になる。会話ログの読み込みは差分読みで、外部のAPI・LLMは使わない。動作確認用の合成データは `node scripts/make-org-chart-sample.mjs <出力先>` で作れる（手順は `sample-data/claude-desktop/README.md` と `/help`。同じ出力先に作り直したときは、ダッシュボードを再起動する）。

## 誤操作からの復旧（退避と保持方針）

実際の `~/.claude` を扱うため、書き換え・削除の前に元の内容を退避し、取り返しのつかない操作を作らない方針にしている。

| 操作 | 退避 | 戻し方 |
|---|---|---|
| ルールの追加・編集・有効/無効・並べ替え・削除（`CLAUDE.md`） | `CLAUDE.md.ccd-backup.<epoch>` | 設定 & システム情報 →「バックアップ」→「復元する」 |
| 実行ログの削除（`execution_log.json`） | `execution_log.json.ccd-backup.<epoch>` | 同上 |
| ルール整理の適用・ルールのインポート | `<ファイル名>.ccd-backup.<epoch>` | 同上 |
| スキルの編集・改名・インポートでの上書き（`SKILL.md`） | `skills/<名前>/SKILL.md.ccd-backup.<epoch>` | 同上 |
| スキルの削除 | `skills-trash/<名前>-<yyyyMMdd-HHmmss>/`（`skills/`の外。Claude Codeからは呼び出されない） | スキル管理 →「削除済みスキル」→「復元する」 |

- ルール・スキル・実行ログの削除は、確認ダイアログを経てから実行される。
- 退避の作成に失敗したときは、書き込み・削除を行わずにエラーにする。
- **保持方針**: 同じファイル（同じスキル名）につき、新しい順に**30世代**まで残し、**90日**より古いものは自動で削除する。ただし最新の**5世代**は期間にかかわらず残す。整理は退避を作るたび（スキルは削除するたび）に自動で行われる。
- 退避ファイル（`*.ccd-backup.*`）は `.gitignore` 済みで、リポジトリには入らない。
- スキル本体（`SKILL.md`）は、編集・改名・インポートでの上書きの直前に退避され、「バックアップ」の一覧から復元できる。削除したスキルは「削除済みスキル」から戻せる。

ナビゲーションは左サイドバーの先頭が「ホーム」（次にやる判断と組織図）で、その下が「Claude Desktop」（セッション一覧・リソース・整理・組織）「設定管理」（ルール管理・スキル管理・設定）「分析・振り返り」（実行ログ・ルール整理）「ツール」（移行・スマホから見る）のカテゴリに分かれ、下部の使い方ガイドを含めて13ページ。
サイドバー下部のボタンでアイコンのみの表示に折りたためる。

## ダウンロード（Windows）

[Releases](../../releases) の最新のリリースから `ClaudeCodeDashboard-<版>-Setup.exe` を取得して実行する。ユーザーごとのインストーラーで、管理者の権限は要らない。1クリックで `%LOCALAPPDATA%\Programs\claude-code-dashboard` に入り、終わるとアプリが起動する。次からはスタートメニューかデスクトップのショートカットから起動する。コード署名は行っていないため、Setup の初回実行時に Windows SmartScreen の警告が出たら「詳細情報」→「実行」で進める。消すときは、Windows の「設定」→「アプリ」→「インストールされているアプリ」からアンインストールする（登録したプロジェクトなどの設定は消えない）。アンインストールの後に、空のフォルダ `%LOCALAPPDATA%\Programs\claude-code-dashboard` が残ることがある。消してよい。サンプルデータを試すときは、同じリリースの `sample-data-v<版>.zip` を使う（下の「サンプルデータを試す」）。

起動の時間は、試した PC（v0.3.2）で、exe を開いてから窓が出るまで約2.3秒だった（入れて最初の起動は約8秒）。遅い PC では、もっとかかることがある（小さな画面に進み具合が出る）。v0.3.1 までの portable の exe は、起動のたびに自分を一時フォルダへ展開していたので（約25〜30秒）、さらに長かった。

「スマホから見る」をオンにしたとき、Windows のファイアウォールの確認が出る。「プライベート ネットワーク」だけを許可する（「パブリック」は許可しない）。入った場所は版を上げても変わらないので、確認はふつう1回だけ。

**v0.3.1 までの portable の exe から移るとき**：Setup で入れると、設定（`%APPDATA%\claude-code-dashboard`）はそのまま使われる。古い portable の exe は消してよい。古い exe が `%TEMP%` に残した展開のフォルダ（`ClaudeCodeDashboard.exe` の入った、名前の長いフォルダ。約770MB）があれば、アプリを閉じてから消してよい。古い場所を許すファイアウォールの許可は、「Windows セキュリティ」→「ファイアウォールとネットワーク保護」→「ファイアウォールによるアプリケーションの許可」で消せる。

## セットアップ

```bash
npm install
npm run dev
```

[http://127.0.0.1:3000](http://127.0.0.1:3000) を開く（開発サーバーは`-H 127.0.0.1`で、このPCの中だけで待ち受ける）。初回は `sample-data/` を対象にしたサンプルプロジェクトが登録済み。

「ルール管理」など設定管理のページの右上の「+」から、`CLAUDE.md`（と任意で `skills/`, `execution_log.json`）を配置している任意の Claude Code
プロジェクト、または実際の `~/.claude` フォルダのルートパスを登録すると、そのプロジェクトを切り替えて管理できる。
パスはディレクトリツリーを辿って選択でき（フォルダ名クリックで選択、シェブロンクリックでインライン展開）、
`CLAUDE.md` / `skills` 等の検出対象には自動でバッジが付く。手入力も可能。

選択中プロジェクトの右隣の鉛筆アイコンから、登録名・パスの編集やダッシュボードからの登録解除（削除）ができる。
実際のフォルダやファイルが削除されるわけではなく、`config/projects.json` 上の登録情報のみが変更される。

> **注意**：`~/.claude` のような実際の設定フォルダを登録すると、本アプリからのトグル/追加/編集/削除がそのまま本番の
> `CLAUDE.md` / `SKILL.md` に書き込まれる。書き込み系の操作を試す際は `sample-data` プロジェクトに切り替えることを推奨する。

`config/projects.json` は個人環境の絶対パスを含むため `.gitignore` 対象。テンプレートは `config/projects.example.json` を参照。

Claude Desktop のデータフォルダ・会話ログのルート（`~/.claude/projects`）・利用上限の記録（`~/.claude-dashboard`）は、既定では自動で探す。場所は `config/desktop-sessions.json`（`dataDir`・`projectsRoot`）・`config/usage.json`（`snapshotsPath`）か、環境変数 `CLAUDE_DESKTOP_DATA_DIR`・`CLAUDE_DESKTOP_PROJECTS_ROOT`（セッション一覧の詳細の「健康」も使う）で指定できる。環境変数 `CCD_DESKTOP_AUTODETECT=0` を付けて起動すると、自動の探索を止め、指定した場所だけを読む（合成データで撮る・確かめるとき用。配布 exe は使わない）。ホームとセッション一覧には、読んでいるデータの出どころ（設定ファイル・環境変数・自動・止めている）を1行で出す。

## Windows向け配布用exeのビルド

Electron + electron-builder で、ユーザーごとに入れるインストーラー（NSIS。管理者の権限は要らない）にパッケージできる。

```bash
npm run dist:win
```

`release/ClaudeCodeDashboard-<version>-Setup.exe`（v0.3.2 なら `ClaudeCodeDashboard-0.3.2-Setup.exe`。版は `package.json` の `version`）が生成される。入れたアプリを起動すると、Next.jsのstandaloneサーバーを
Electronの内部プロセスとして起動し、ネイティブウィンドウでダッシュボードを表示する（外部ブラウザ不要）。

- 初回起動時のみ、`config/projects.example.json`（個人パスを含まない空のテンプレート）を、OSごとの
  ユーザーデータ領域（Windowsなら `%APPDATA%/claude-code-dashboard`）へ複製する。以後の登録・編集内容はすべて
  そこに永続化され、アプリの入れ直し（上書き）やアンインストールには影響されない。
- `electron/main.js` が起動処理の実体。`electron-builder.yml` の `extraResources` で、実行に必要な
  `.next/standalone`（node_modules・サーバー本体）と上記のテンプレートのみを明示的に同梱している
  （サンプルデータや `config/projects.json` 等、個人データ・非本質的なファイルは同梱しない）。
- 内部サーバーは**優先ポート `38417`（127.0.0.1）**で起動し、そのポートが使用中のときだけ空いているポートで起動する
  （`electron/port.js`）。画面の設定（サイドバーの折りたたみ・各種の絞り込みなど）はブラウザの `localStorage` に
  保存され、保存先はポートを含むオリジンごとに分かれるため、毎回同じポートで起動することで次回の起動にも引き継がれる。
  **優先ポートが使用中のとき**（exeを二重に起動した・他のアプリが使っている・前回のサーバーが終了しきれていない等）は、
  その起動の間だけ別のオリジンになり、`localStorage` の設定は優先ポートで起動したときの内容とは**別扱い**
  （空の状態から始まり、その起動で変えた設定も優先ポートの起動には反映されない）。このときは起動ログに
  `[port]` の警告が出る。デスクトップ通知のオン・オフは、この影響を受けないようサーバー側のファイル
  （`config/desktop-notify.json`）に保存している。`/api/*` のHost/Origin検証はポートを問わないため、どちらのポートでも動く。
- コード署名は行っていないため、Setup の初回実行時にWindows SmartScreenの警告が出る（「詳細情報」→「実行」で進める）。
- 起動中は進捗％と残り時間の目安を表示する小さなスプラッシュ画面（`electron/splash.html`）を表示する。表示するのは「サーバー起動〜画面描画」の区間。
- 配り方は、ユーザーごとに入れるインストーラー（`electron-builder.yml` の `win.target: nsis`。oneClick・perMachine は既定のまま）で、入れる場所（`%LOCALAPPDATA%\Programs` の下）は版を上げても同じ。
  v0.3.1 までは portable exe で、起動のたびに自分を一時フォルダへ自己展開していた（約25〜30秒）。展開先が起動ごとに変わる作りでは、「スマホから見る」のファイアウォールの確認が起動のたびに出る見込みになるため、v0.3.2 でインストーラーに変えた。
  2つ目を起動すると、二重起動の防止で、開いている窓が前に出る。
- サーバーの立ち上がりは、データを読まない軽い入り口（`/api/health`）で確かめる（`electron/startup.js`）。全体の待ちに締め切りは置かず、
  前回の起動の3倍（最低60秒・最大10分。段階の時計と同じ所から数える）を過ぎても準備が終わらないときは、終了せずにスプラッシュに「まだ準備中です」と出し、
  ［待つ］・［やめる］を選べる（秒は「この画面が出てから〇秒」の1か所だけ。20秒を過ぎたら、目安の前でも小さな［やめる］を出す）。段階ごとの時間（seed・spawn・next-ready・http-ok・page-loaded）と結果は、ユーザーデータ領域の
  `startup-stats.json` に残す（時間と結果と回数だけで、パスは書かない）。サーバーのプロセスが途中で終わったときだけ「起動エラー」を出す。

### サンプルデータを試す

アプリにはサンプルデータを同梱していない（本体を必要最低限に保つため）。試したい場合は、Releaseページから
`sample-data-v<version>.zip`（v0.3.2 なら `sample-data-v0.3.2.zip`）を別途ダウンロードして展開し、「ルール管理」の右上の「+」からその展開先フォルダを
プロジェクトとして登録する。`npm run package:sample-data` でこのzipをリポジトリの `sample-data/` から生成できる。
