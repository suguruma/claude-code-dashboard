# Claude Code Dashboard

Claude Code とのやり取りにおける「ルール」「スキル」「実行ログ／思考プロセス」をローカルで可視化・管理するダッシュボード。
Webアプリ側は重い処理を行わず、実際の `.claude/CLAUDE.md` / `.claude/skills/*/SKILL.md` / `execution_log.json` を直接
読み書きして描画するだけのCPUモード（外部API通信なし・コスト0円）で動作する。

## 実装済み機能

- **ルール管理**（`/rules`）— `CLAUDE.md` の `## 見出し` をルールとして直接パース。ON/OFFトグル（`<!-- CCD:DISABLED -->` で無効化）、追加/編集/削除（削除は確認ダイアログつき。CLAUDE.mdを書き換えるたびに直前の内容を自動で退避）、ドラッグ&ドロップによる表示順（=CLAUDE.mdの記載順）の並び替え、次回用プロンプト集（実行ログ由来）
- **スキル管理**（`/skills`）— `.claude/skills/*/SKILL.md` の一覧・追加・編集・削除（確認ダイアログつき。完全削除はせず`skills-trash/`へ退避し、「削除済みスキル」から復元できる）・改名（ディレクトリ名変更。呼び出しコマンドが変わる旨を確認表示）・カテゴリ別グルーピング表示（frontmatterの`category`フィールドに基づく表示上の分類。実ファイルはフラット配置のまま）・成熟度バッジ（`references`/`scripts`/`evals`サブフォルダの有無を表示）・対象モデルの記録（frontmatterの`target-model`。自由入力。一覧に🎯バッジで表示）
- **メモリ管理**（`/memory`）— `.claude/projects/*/memory/*.md`（AIメモリシステム）の一覧・閲覧。type別（user/feedback/project/reference）フィルタ。読み取り専用
- **タスク実行履歴**（`/tasks`）— `.claude/tasks/<session-id>/*.json` をセッション別に進捗バー・ステータスアイコン付きで可視化。読み取り専用
- **設定 & システム情報**（`/settings`）— `settings.json`（権限モード・環境変数・statusLine）/ バックアップ / ブロック済みプラグイン一覧をTabsで表示。バックアップのタブには、Claude Code本体の`.claude.json`バックアップと、このダッシュボードが書き換え・削除の直前に作った退避（`*.ccd-backup.<epoch>`）が並び、復元できる（復元の直前の内容も退避される）。プラグインは読み取り専用
- **移行（エクスポート/インポート）**（`/migrate`）— ルール・スキルを1つのJSONファイルに書き出し、他のPC（別プロジェクト）に差分プレビュー付きで取り込む。上書き前に自動バックアップ。インポートの「ファイルを選択」はドラッグ&ドロップにも対応し、配布版exeでは`dialog.showOpenDialog`をIPC経由で直接呼び出す経路を優先する（環境差でファイル選択ダイアログが開かない事例への対処）
- **セッション監視**（`/session-monitor`）— `~/.claude/projects/*/*.jsonl`（Claude Codeの実行ログ）を解析し、**そのセッションが健全かを8つの観点で診断**する。セッションの寿命（コンパクション）・無限ループの兆候（エラー率）・読み取りの精度・コストと応答速度（キャッシュヒット率）・ワークフローの安定性・作業の分業・MCPの稼働・お任せ度をそれぞれ良好/注意/要対処で判定し、`/clear`でのリセットやgrepでの読み取り範囲の限定といった**具体的な対処を提示**する。判定の根拠としきい値も併記するため、しきい値の妥当性を自分で確認できる。数値の多寡は単独では判断できないため、同一プロジェクトの過去セッションを古い順に並べた推移グラフ（選択中のみ強調）と中央値との比較を用意。セッション一覧には先頭発話の抜粋（表示名）と発火したスキル名を表示し、どのやりとりだったか判別できるようにしている。生の集計値と個別グラフ（トークン推移・ツール呼び出し・MCP別・出力サイズ・圧縮履歴）は「詳細データ」を開いたときだけ取得・表示し、初期表示のペイロードを抑えている。Claude Code側のスキル`session-diagnostician`を実行すると、要求の誤解・手戻りの繰り返しといった意味的な診断（AI診断）も併記表示される（ダッシュボード自身はLLMを呼ばない方針のため、スキルが生成する`session_diagnosis.json`を読むだけ）。自動更新トグルで3秒間隔のポーリングにも対応。読み取り専用
- **セッション一覧**（`/desktop-sessions`）— Claude Desktopの全セッションを一覧する読み取り専用ビュー（5秒更新。サイドバーの「Claude Desktop」は、見たい内容ごとに「セッション一覧」「組織図」「利用上限」「整理」の4ページに分かれている）。一覧の主データはDesktopが保存するセッションのメタデータ（`claude-code-sessions/*/*/local_*.json`）で、要対応のセッションには要対応の内容の先頭60文字を表示し、会話ログ（`~/.claude/projects/*/<id>.jsonl`）から最新の指示（先頭60文字・発信元つき）・コンテキスト使用量・タスクリストの進み具合・圧縮回数を補い、サイドバーのグループ・ピン留めは`claude_desktop_config.json`の`preferences.epitaxyPrefs`の該当キーだけを読む。状態は、Desktopが付ける分類（要対応・確認待ち・完了）と、会話ログの更新状況からの推定（実行中・中断の可能性）を併記する。Desktopの内部形式は非公開・非保証のため読み取り処理は`src/lib/desktopSessions.ts`に隔離し、読めない場合は会話ログだけの縮退表示に切り替える。認証トークンを含む`config.json`は読まず、APIは表示用の許可リスト項目だけを返す。新しく要対応になったセッションのデスクトップ通知（初期値はオフ。exeはElectron、ブラウザはNotification API。外部サービスは使わず、本文はセッション名と要対応の内容の抜粋だけ。クリックで詳細を開く）と、起動中のclaude.exe（`--resume=<id>`）の有無の「CLIプロセスあり」表示（固定のPowerShellで`--resume`のIDだけを取得し、「実行中」とは別の表示）に対応。他のセッションへのメッセージ送信には「人が最後に入力してから10回まで」という上限があるため、各セッションに**送信回数**（送信 n/10。8回以上で黄、10回で赤。届かなかった送信も数える）を表示し、上限で止まっているセッションは**「送信上限で停止中」**を赤で目立たせて、Claude Desktopでそのセッションを開くボタン（`claude://`のリンク。exeは許可した形式のURLだけを開く）を出す。新しく停止したときのデスクトップ通知（要対応の通知と同じスイッチ）にも対応。回数は会話ログの送信ツール（`SendMessage`・セッション管理の送信ツール）の呼び出しから数え、停止は送信ツールの結果の文言から判定する（文言は非保証のため、判定条件は`src/lib/sessionMessaging.ts`の1か所に集約）。サンプルは`sample-data/claude-desktop/`（すべて合成データ）
- **利用上限の可視化**（`/desktop-sessions/usage`）— 5時間・週（全モデル）・週（モデル別）の上限のゲージ（80%で黄・90%で橙・95%で赤）、リセットまでの残り時間、今のペースで何時に100%になるか（リセットより先に達する場合は警告。リセットとの差が小さい場合〈5時間の枠は15分以内・週の枠は2時間以内〉は赤でなく黄色で「リセットとほぼ同時」）、直近5時間と今週にどのセッション・グループが使っているか（上限の何%に当たるかで表す積み上げ棒。ドルは請求額と誤解されるため出さず、係数が決まらないときは全体に占める割合）を表示する。80%・95%を超えたときのデスクトップ通知（要対応の通知と同じスイッチ）、最新の公式値が80%以上（「上限に近づいています」）・90%以上（「上限ガード中：新しい指示は保留中です」）のときの帯（Claude Desktopの3ページの上部に表示。表示のみ。ガードの判断は運用ルール側）に対応。**公式値**は`~/.claude-dashboard/usage-snapshots.jsonl`（1行1件。記録は別の運用で追記する）を読み取るだけで、書かない。公式値の記録の間は、会話記録（`~/.claude/projects/*/*.jsonl`と`<セッション>/subagents/*.jsonl`）のトークン量を、`message.id`で重複を除いたうえでAPI価格で金額に換算し、公式値で較正した係数で割って**推定**する（画面には「推定」と幅を明示し、直近7日の公式値との差の中央値・90%点も表示）。モデルの価格表は`config/usage.json`の`prices`で直せる（見本は`config/usage.example.json`）。認証情報（`.credentials.json`・Desktopの`config.json`）は読まない。外部との通信なし・LLM呼び出しなし
- **組織図**（`/desktop-sessions/org`）— グループごとに、指揮役のカードを上に、グループ内のセッションのカードを下に並べ、指示（指揮役→子、青い粒が下へ）・報告（子→指揮役、緑の粒が上へ。粒の大きさは作業量）・他のグループや外部（CLI）からの連絡（紫の点線）を線の上の動きで見せる読み取り専用ビュー。指示と他グループ連絡は先頭20文字だけを線の横に出し、報告の本文は出さない。報告せずにターンが終わったセッションは灰色の「報告なしで終了」、作業中のカードは脈動し、コンテキストは80%で黄・90%で赤、圧縮と増えた分（+28K など）も一瞬示す。「ライブ」は新しく起きた出来事だけを流し、「振り返り」は再生・一時停止・速さ（×60／×300／×900）・空き時間を飛ばす・再生位置のスライダーで過去4時間（1時間・24時間も選べる）を再現する。子のカードの並び順は、名前の自然順（`01_` `02_` `10_` の順。既定）と作成順を、画面の「並び順」で切り替えられる（指揮役は常に最上段）。指揮役は、グループ内でタイトルが接頭辞（既定 `00_`）で始まるセッション。接頭辞は `config/desktop-sessions.json` の `orchestratorPrefix` で変える（設定を変えたら再起動）。接頭辞に合うセッションが無いグループは、カードだけを並べて線は引かない。指揮役の子（2層目）が作った補助のセッション（例: 会話の練習相手）は、その子のカードの下に字下げして並べ、子から線でつなぐ（3層目）。親は、Desktopのメタデータの `spawnedFrom.sessionId`（そのセッションを作ったセッション）だけで判断し、作業フォルダやタイトルは使わない。3層目はグループに入っていなくても出る（親が2層目の子のときだけ）。3層目が作ったセッション（4層目以降）は、2層目の祖先の下にまとめて並べ、アーカイブ済みは出さない。指揮役がいないグループは、3層目も出さない。親子の間の指示・報告は、2層目と同じ規則で粒を流す。指示が無くても、直近1分以内にツールを呼んでいれば、カードは「作業中」になる。指揮役のカードの「指示 n／報告 n」は指揮役自身の分で、3層目の出来事は含まない（上の概要の数と出来事の一覧は含む）。会話ログの読み込みは差分読みで、外部のAPI・LLMは使わない。動作確認用の合成データは `node scripts/make-org-chart-sample.mjs <出力先>` で作れる（手順は `sample-data/claude-desktop/README.md` と `/help`）。会話ログの読み込みは差分読みなので、同じ出力先に合成データを作り直したときは、ダッシュボードを再起動する（再起動しないと、古い値のまま）。
- **セッションの整理**（`/desktop-sessions/housekeeping`）— たまったセッションを片づけるための、読み取り専用の1画面。(1) **あなたの判断を待っているセッション**: 要対応・送信上限で停止中・エラー・届かなかった送信があるセッションを、全グループ（グループ外を含む）から集める。(2) **返事の来ていない指示**: 直近24時間に指揮役などが送った指示のうち、報告が付いていないもの（報告なしで終了／報告待ち〈30分以上〉／未達の疑い〈送り手の記録だけで、30分以上〉）を、組織図と同じ出来事の組み立て（`assembleFlow`）から取り出す。(3) **コンテキスト整理の候補**: コンテキスト使用率が高い（`highContextRatio`、既定80%）、または最後の応答から60分以上たって50K以上のセッション（実行中・アーカイブ済みは除く）。最後の応答から1時間たつとプロンプトキャッシュが切れ、再開した最初の応答でコンテキスト全体を書き直すため、その**再開コスト**（コンテキスト量×入力単価×2〔1時間キャッシュの書き込み〕）を、利用上限の較正があれば「5時間の枠 約x〜y%・週 約x〜y%」で、金額（API価格換算。請求額ではない）を添えて出し、再開コストの大きい順に並べる。キャッシュ切れの行には「使わないなら、再開せずに /clear か圧縮」の案内を添える。各行の「セッションを開く」で、Claude Desktopでそのセッションを開く（許可した形式のURLだけ）。しきい値は`config/desktop-sessions.json`の`housekeeping`（`idleMinutes`・`minIdleTokens`・`unansweredMinutes`）で変える。会話の本文は返さず、返すのはタイトル・グループ名・モデル・時刻・数値・状態・指示の先頭20文字・要対応の先頭60文字だけ。外部との通信なし・LLM呼び出しなし
- **実行ログ & 思考プロセス可視化**（`/trace`）— エージェント議論・合意度メーター・トレードオフ比較・介入ハイライト・次回用プロンプトのワンクリック保存。マルチエージェント構成図（指揮系統の肩書きはログごとに指定可能。無指定ならフラットなチーム編成として表示）と試行錯誤・リトライのタイムラインにも対応。`execution_log.json`自体は本ダッシュボードは生成せず、Claude Code側のスキル（5役体制の`autonomous-production-team`、または通常の会話を事後的に記録する`session-log-extractor`）が書き出す。書き出し先はスキルを実行した作業ディレクトリになるため、ページ上部の「分析対象プロジェクト」セレクター（TopBarの選択中プロジェクトとは独立、登録済みプロジェクトから選択）で見たいプロジェクトを切り替える。ルール保存先（CLAUDE.md）はTopBarの選択中プロジェクト側になる
- **使い方ガイド**（`/help`）— 初心者向けの用語集・各ページの使い方・FAQをまとめた解説ページ。サイドバー下部に常時リンクを表示
- **ルール整理**（`/refactor`）— Claude Code標準スキル`rule-optimizer`（execution_log.jsonの過去のユーザー介入履歴から矛盾・重複ルールを学習）が出力する`rule_refactor_proposal.json`を読み込み、現在のCLAUDE.mdとのDiffプレビュー・ステイル検知（提案生成後の編集を検知）・選択適用（バックアップ付き）を行う。ローカルLLM（GPUモード）連携構想は方針転換により廃止し、このスキル連携方式に統一した。`/trace`と同様、ページ上部の「分析対象プロジェクト」セレクターがTopBarの選択中プロジェクトとは独立しており、適用先のCLAUDE.mdもこのセレクターで選んだプロジェクトになる
- 複数プロジェクトの横断管理（画面右上のプロジェクトスイッチャー。実際の `~/.claude` をプロジェクトとして登録することも可能）
- ライト/ダーク/システム追従のテーマ切替（TopBar右側）

メモリ管理・タスク実行履歴・プラグイン一覧・セッション監視は読み取り専用。
移行機能はルール・スキルのみが対象で、settings.jsonの環境変数などは含まない。

## 誤操作からの復旧（退避と保持方針）

実際の `~/.claude` を扱うため、書き換え・削除の前に元の内容を退避し、取り返しのつかない操作を作らない方針にしている。

| 操作 | 退避 | 戻し方 |
|---|---|---|
| ルールの追加・編集・有効/無効・並べ替え・削除（`CLAUDE.md`） | `CLAUDE.md.ccd-backup.<epoch>` | 設定 & システム情報 →「バックアップ」→「復元する」 |
| 実行ログの削除（`execution_log.json`） | `execution_log.json.ccd-backup.<epoch>` | 同上 |
| 設定の保存（`settings.json`）・ルール整理の適用・ルールのインポート | `<ファイル名>.ccd-backup.<epoch>` | 同上 |
| スキルの削除 | `skills-trash/<名前>-<yyyyMMdd-HHmmss>/`（`skills/`の外。Claude Codeからは呼び出されない） | スキル管理 →「削除済みスキル」→「復元する」 |

- ルール・スキル・実行ログの削除は、確認ダイアログを経てから実行される。
- 退避の作成に失敗したときは、書き込み・削除を行わずにエラーにする。
- **保持方針**: 同じファイル（同じスキル名）につき、新しい順に**30世代**まで残し、**90日**より古いものは自動で削除する。ただし最新の**5世代**は期間にかかわらず残す。整理は退避を作るたび（スキルは削除するたび）に自動で行われる。
- 退避ファイル（`*.ccd-backup.*`）は `.gitignore` 済みで、リポジトリには入らない。
- スキル本体の編集（`SKILL.md`）は退避の対象外（スキルのモデル別アーカイブ機能を使う）。スキルのインポートで上書きされる `SKILL.md` は `skills/<名前>/SKILL.md.ccd-backup.<epoch>` に退避されるが、バックアップ画面の一覧には出ない（ファイルを直接戻す）。

ナビゲーションは左サイドバーに「設定管理」「Claude Desktop」「分析・振り返り」「ツール」のカテゴリでグループ化されている（「Claude Desktop」は、セッション一覧・組織図・利用上限・整理の4ページ）。
サイドバー下部のボタンでアイコンのみの表示に折りたためる。

## セットアップ

```bash
npm install
npm run dev
```

[http://localhost:3000](http://localhost:3000) を開く。初回は `sample-data/` を対象にしたサンプルプロジェクトが登録済み。

画面右上の「+」から、`CLAUDE.md`（と任意で `skills/`, `execution_log.json`）を配置している任意の Claude Code
プロジェクト、または実際の `~/.claude` フォルダのルートパスを登録すると、そのプロジェクトを切り替えて管理できる。
パスはディレクトリツリーを辿って選択でき（フォルダ名クリックで選択、シェブロンクリックでインライン展開）、
`CLAUDE.md` / `skills` 等の検出対象には自動でバッジが付く。手入力も可能。

選択中プロジェクトの右隣の鉛筆アイコンから、登録名・パスの編集やダッシュボードからの登録解除（削除）ができる。
実際のフォルダやファイルが削除されるわけではなく、`config/projects.json` 上の登録情報のみが変更される。

> **注意**：`~/.claude` のような実際の設定フォルダを登録すると、本アプリからのトグル/追加/編集/削除がそのまま本番の
> `CLAUDE.md` / `SKILL.md` に書き込まれる。書き込み系の操作を試す際は `sample-data` プロジェクトに切り替えることを推奨する。

`config/projects.json` は個人環境の絶対パスを含むため `.gitignore` 対象。テンプレートは `config/projects.example.json` を参照。

## Windows向け配布用exeのビルド

Electron + electron-builder で、インストール不要のポータブルexe（1ファイル）にパッケージできる。

```bash
npm run dist:win
```

`release/ClaudeCodeDashboard-<version>-portable.exe` が生成される。実行すると、Next.jsのstandaloneサーバーを
Electronの内部プロセスとして起動し、ネイティブウィンドウでダッシュボードを表示する（外部ブラウザ不要）。

- 初回起動時のみ、`config/projects.example.json`（個人パスを含まない空のテンプレート）を、OSごとの
  ユーザーデータ領域（Windowsなら `%APPDATA%/claude-code-dashboard`）へ複製する。以後の登録・編集内容はすべて
  そこに永続化され、exe本体の再配布・上書きには影響されない。
- `electron/main.js` が起動処理の実体。`electron-builder.yml` の `extraResources` で、実行に必要な
  `.next/standalone`（node_modules・サーバー本体）と上記のテンプレートのみを明示的に同梱している
  （サンプルデータや `config/projects.json` 等、個人データ・非本質的なファイルは同梱しない）。
- 内部サーバーは**優先ポート `38417`（127.0.0.1）**で起動し、そのポートが使用中のときだけ空いているポートで起動する
  （`electron/port.js`）。画面の設定（サイドバーの折りたたみ・各種の絞り込みなど）はブラウザの `localStorage` に
  保存され、保存先はポートを含むオリジンごとに分かれるため、毎回同じポートで起動することで次回の起動にも引き継がれる。
  **優先ポートが使用中のとき**（exeを二重に起動した・他のアプリが使っている・前回のサーバーが終了しきれていない等）は、
  その起動の間だけ別のオリジンになり、`localStorage` の設定は優先ポートで起動したときの内容とは**別扱い**
  （空の状態から始まり、その起動で変えた設定も優先ポートの起動には反映されない）。このときは起動ログに
  `[port]` の警告が出る。デスクトップ通知のオン・オフは、この影響を受けないようサーバー側のファイル
  （`config/desktop-notify.json`）に保存している。`/api/*` のHost/Origin検証はポートを問わないため、どちらのポートでも動く。
- コード署名は行っていないため、初回実行時にWindows SmartScreenの警告が出る（「詳細情報」→「実行」で起動可能）。
- 起動中は進捗％と残り時間の目安を表示する小さなスプラッシュ画面（`electron/splash.html`）を表示する。
  **注意**：portable exeは起動のたびにOSレベルで自身を一時フォルダへ自己展開してからアプリ本体が動き出すため
  （実測で起動時間の大半を占める）、スプラッシュはその自己展開フェーズ**より後**の「サーバー起動〜画面描画」
  区間しか可視化できない。

### サンプルデータを試す

exe本体にはサンプルデータを同梱していない（本体を必要最低限に保つため）。試したい場合は、Releaseページから
`sample-data-v<version>.zip` を別途ダウンロードして展開し、アプリ右上の「+」からその展開先フォルダを
プロジェクトとして登録する。`npm run package:sample-data` でこのzipをリポジトリの `sample-data/` から生成できる。
